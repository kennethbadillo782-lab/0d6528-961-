PROYECTO: MI CATÁLOGO DE MODA

Especificación completa de diseño y desarrollo para iPhone

1. Objetivo principal

Quiero desarrollar una aplicación personal para iPhone basada en la imagen de referencia adjunta.

La aplicación será un catálogo privado de ropa, accesorios, joyería, calzado y artículos de moda que quiero comprar en el futuro.

No es una tienda online, no necesito vender productos y no necesito un sistema de pagos dentro de la aplicación.

El propósito es descubrir, añadir, guardar, organizar, filtrar y consultar todos los productos que voy encontrando por internet.

Por ejemplo, puedo encontrar una cartera en Hipobuy, unos pantalones en Taobao o unas pantallas en otra tienda. Quiero poder guardar cada artículo con sus fotografías, precio, vendedor, enlace de compra y características, y encontrarlo posteriormente con facilidad.

La aplicación debe funcionar como una mezcla entre una tienda de moda moderna y una lista de deseos personal, con una experiencia muy visual.

2. Requisito fundamental: diseño

La imagen adjunta contiene 10 pantallas que representan el diseño aprobado.

No quiero un rediseño, otra paleta de colores ni una interpretación genérica.

Debes replicar lo más fielmente posible:

* La distribución de los elementos.
* Las proporciones de las fotografías.
* El tamaño y estilo de las tarjetas.
* La navegación inferior.
* Las barras de búsqueda.
* Las etiquetas de filtros.
* Los botones redondeados.
* El espaciado y las jerarquías visuales.
* La apariencia oscura y minimalista.

La referencia muestra una app negra, elegante, moderna, con fotografías grandes y controles compactos.

Quiero que se sienta como una aplicación real de iOS de alta calidad, no como una página web genérica introducida dentro de un teléfono.

3. Tecnología y dispositivo

Dispositivo principal: iPhone 17 Pro Max.

Preferencia técnica: Swift y SwiftUI, para una aplicación nativa de iOS.

Requisitos:

* Modo oscuro permanente.
* Adaptación a las áreas seguras del iPhone y Dynamic Island.
* Navegación fluida y transiciones nativas.
* Desplazamiento vertical suave.
* Animaciones discretas.
* Interfaz táctil cómoda.
* Fotografías de alta calidad.
* Persistencia real de los productos.
* Funcionamiento sin conexión para los datos guardados localmente.
* Arquitectura preparada para incorporar sincronización en la nube posteriormente.

Para la primera versión se puede utilizar SwiftData como almacenamiento local. Si posteriormente necesito sincronización entre dispositivos o integración con ChatGPT, podremos incorporar un backend.

4. SISTEMA VISUAL

Paleta de colores

Usar los siguientes colores como orientación, ajustándolos para coincidir lo mejor posible con la fotografía:

Elemento	Color aproximado
Fondo principal	#080B0E
Tarjetas	#1B1F24
Barras de búsqueda	#20242A
Texto principal	#FFFFFF
Texto secundario	#A0A5AD
Botones de filtro	#24282D
Azul de selección	#287BFF
Corazones activos	#F04C79
Bordes discretos	#30343A

No crear contornos blancos gruesos, sombras exageradas ni degradados innecesarios.

Los elementos deben separarse utilizando principalmente espacio, contraste y superficies ligeramente distintas.

Tipografía

Usar el sistema tipográfico nativo de Apple: SF Pro.

* Encabezados principales: semibold o bold.
* Títulos de producto: semibold.
* Precios: medium o semibold.
* Descripciones: regular.
* Etiquetas pequeñas: regular o medium.

La aplicación debe tener una excelente legibilidad sin desperdiciar demasiado espacio.

Tarjetas de producto

Cada artículo se presenta utilizando una tarjeta que contiene:

1. Fotografía principal grande.
2. Corazón en la esquina superior derecha.
3. Nombre del producto.
4. Precio.
5. Información adicional cuando corresponda.

Las fotografías deben ocupar la mayor parte de la tarjeta.

La cuadrícula principal utilizará dos columnas en iPhone, como aparece en la imagen.

Puede guardar un artículo aunque todavía no tenga su enlace de compra.

Permitir buscar entre los productos que ya tiene guardados.

En una versión posterior se podrá incorporar búsqueda externa mediante una API o servicio compatible.

No asumir que todos los marketplaces ofrecen búsqueda pública automatizada.

18. MONEDAS Y PRECIOS

Vivo en Puerto Rico, así que prefiero utilizar USD ($) como moneda principal.

Sin embargo, muchos productos proceden de China y tendrán precios en yuanes (CNY).

Quiero poder almacenar:

* Precio original en su moneda.
* Precio equivalente en USD.
* Costo estimado de envío.
* Costo final estimado.

Las conversiones deben mostrar cuándo se actualizó el tipo de cambio.

Si no existe un tipo de cambio disponible, presentar el precio original sin inventar una conversión exacta.

No necesito un sistema de checkout. Las compras se harán en las páginas externas.

19. EXPERIENCIA DE USUARIO

La aplicación debe sentirse rápida, agradable y terminada.

Interacciones

* Tocar un producto abre sus detalles.
* Tocar un corazón activa o desactiva favorito inmediatamente.
* Mantener pulsado un producto puede abrir un menú de acciones.
* Las colecciones permiten añadir múltiples artículos.
* Las búsquedas y filtros se actualizan sin retrasos innecesarios.
* Los formularios conservan los datos hasta guardar o cancelar.
* Los botones ofrecen retroalimentación táctil discreta cuando corresponda.

Estados especiales

Crear pantallas apropiadas para:

* Catálogo vacío.
* Sin resultados de búsqueda.
* Error al cargar imágenes.
* Enlace no compatible.
* Producto duplicado.
* Falta de conexión.
* Producto guardado correctamente.
* Confirmación antes de eliminar.

Evitar pantallas vacías sin explicación y botones que no hagan nada.

Rendimiento

Utilizar carga diferida de fotografías, caché de imágenes y listas eficientes.

Debe poder almacenar cientos o miles de productos sin degradarse de forma notable.

20. FUTURA INTEGRACIÓN CON CHATGPT

Este requisito es importante para el proyecto completo, aunque no necesita estar terminado en la primera versión.

Quiero poder conversar con ChatGPT y decir:

“Busca 10 carteras negras y guárdame las mejores en mi aplicación”.

El objetivo futuro es que los artículos lleguen al catálogo sin tener que introducirlos manualmente uno por uno.

Para permitirlo, diseñar la arquitectura de forma que posteriormente pueda ofrecer una API autenticada para:

* Crear productos.
* Modificar productos.
* Consultar productos.
* Añadir imágenes.
* Gestionar colecciones.
* Marcar favoritos.

La sincronización externa no debe considerarse implementada hasta conectar y probar realmente esos servicios.

Por ahora, priorizar la entrada manual por enlaces y fotografías.

22. ORDEN DE IMPLEMENTACIÓN

Desarrollar en el siguiente orden:

Fase 1 — Diseño y navegación

Construir las diez pantallas de referencia y la pestaña Cuenta.

Utilizar datos demostrativos para verificar visualmente el resultado.

Implementar navegación real entre pantallas.

Fase 2 — Almacenamiento

Crear modelos persistentes y sustituir las listas demostrativas por datos guardados.

Implementar favoritos, colecciones, búsqueda y filtros.

Fase 3 — Añadir artículos

Implementar formularios completos, importación de imágenes y guardado de enlaces.

La extracción automática de información desde enlaces será progresiva y tendrá siempre una opción manual.

Fase 4 — Experiencia y calidad

Completar estados vacíos, gestión de errores, edición, eliminación, ordenación, rendimiento y pulido visual.

Fase 5 — Funciones posteriores

Sincronización en la nube, integración con ChatGPT, importación masiva y actualizaciones de precios cuando existan fuentes compatibles.

23. REGLAS PARA EL DESARROLLO

1. La imagen es la referencia visual principal. No rediseñar la aplicación sin autorización.
2. No construir solamente una maqueta: quiero pantallas conectadas, botones funcionales y almacenamiento real.
3. No presentar productos demostrativos como si fueran artículos guardados por el usuario.
4. No inventar valoraciones, precios, descuentos, fotografías QC ni garantías de calidad.
5. No hacer depender la aplicación de un solo agente o tienda.
6. Permitir guardar productos aunque no tengan enlace, precio o todas sus fotografías.
7. Diseñar todos los componentes para que puedan ampliarse sin reconstruir la aplicación.
8. Mantener los datos del usuario separados de las imágenes o productos demostrativos.
9. No implementar pagos ni funciones comerciales innecesarias.
10. Probar los flujos completos en el simulador de iPhone y, cuando sea posible, en el dispositivo real.

24. RESULTADO FINAL ESPERADO

Quiero abrir la aplicación en mi iPhone y encontrar una experiencia como la imagen de referencia.

Desde Inicio podré entrar a Carteras, Camisas, Pantalones, Pantallas o cualquier otra categoría.

Dentro de cada una veré mis productos organizados visualmente, con fotografías grandes, filtros útiles y precios claros.

Podré seleccionar un producto para ver todas sus imágenes, inspeccionar sus detalles y abrir el enlace de compra.

También podré pegar un enlace nuevo, subir fotos, asignarle una categoría y guardarlo en una colección.

Con el tiempo tendré cientos o miles de artículos organizados, preparados para comprarlos cuando quiera.

El objetivo no es crear un marketplace. Es crear mi catálogo personal de moda, con la calidad visual y comodidad de una aplicación comercial de primera categoría.

Empieza implementando la base del proyecto, la navegación y las pantallas de la imagen. Después completa la persistencia y el funcionamiento de cada módulo. Conserva siempre el diseño aprobado y entrega código ejecutable, no solamente una explicación de cómo construirlo.
